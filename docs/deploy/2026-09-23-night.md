### B1. `stop_grace_period: 60s` for postgres, scylla, kafka

The pull in A0 brought it (`docker-compose.prod.yml`, on the three stateful services). It applies
**only when a container is recreated or the host reboots** — `restart` keeps the old 10 s. Recreate
the three now, one at a time, so a failure is contained:

```bash
grep -n "stop_grace_period" docker-compose.prod.yml
docker compose -f docker-compose.prod.yml up -d --no-deps postgres
docker compose -f docker-compose.prod.yml --profile scylla up -d --no-deps scylla
docker compose -f docker-compose.prod.yml --profile kafka up -d --no-deps kafka
sleep 20
for c in postgres scylla kafka; do
  printf '%-10s StopTimeout=%s\n' "$c" "$(docker inspect "$(docker compose -f docker-compose.prod.yml --profile kafka --profile scylla ps -q $c)" --format '{{.Config.StopTimeout}}')"
done
docker compose -f docker-compose.prod.yml exec -T postgres pg_isready -U chat_user -d chat_platform
docker compose -f docker-compose.prod.yml --profile scylla exec -T scylla cqlsh -e "describe cluster" >/dev/null && echo "scylla CQL OK"
docker compose -f docker-compose.prod.yml --profile kafka exec -T kafka /opt/bitnami/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list | head -3
curl -s -o /dev/null -w 'api %{http_code}\n' https://api.growblic.com/health
```
